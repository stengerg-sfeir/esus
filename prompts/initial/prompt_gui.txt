Build a Python 3.12 application for a local wine shop owner to manage their premium wine inventory and tracks bottle storage locations.

The system must satisfy the following criteria:

1. Core Features & Architecture:
   - Provide a responsive GUI (Graphical User Interface) for the shop owner to visually manage the bottles, update stock levels, and assign bottles to physical locations (e.g., Rack A, Shelf 3).
   - The application must persist all data locally across sessions.
   - Enforce a strict separation between the visual presentation layer, the data persistence access layer, and the core domain logic.

2. Expected Data Structure:
   - Wine Model: unique identifier, name, vintage year (int), wine type (red, white, rosé, sparkling), country of origin, cost price, selling price, and total current stock quantity.
   - Storage Location Model: unique identifier, zone name (e.g., "Main Cellar", "Front Display"), row number, shelf number, and maximum bottle capacity.
   - Each wine bottle entry must point to exactly one primary storage location.

3. Key Constraints & Rules:
   - The selling price of a wine bottle must always be strictly greater than its cost price.
   - A wine's stock quantity can never drop below zero.
   - The total number of bottles assigned to a specific storage location cannot exceed that location's defined maximum bottle capacity.
   - All wine names must be unique in the system.
   - Prevent the removal of a storage location if wine bottles are currently assigned to it.

4. Robustness:
   - Implement clean user validation with intuitive error handling.
   - Raise custom domain exceptions when business constraints are violated, such as NegativeStockError, LocationOverCapacityException, or InvalidPricingException.
