Create a multi-module Python library management system with the following features:

1. **Book model** — id, title, isbn (unique), published_year, available_copies (default 1)
2. **Author model** — id, name, birth_year, biography
3. **Member model** — id, name, email (unique), membership_date, is_active (default True)
4. **Loan model** — id, book_id (FK), member_id (FK), loan_date, due_date, return_date (nullable), status (active/returned/overdue)
5. **BookRepository** — SQLite storage with CRUD + search by title/author/isbn + filtering by available copies
6. **AuthorRepository** — SQLite storage with CRUD + find books by author
7. **MemberRepository** — SQLite storage with CRUD + find active/inactive members
8. **LoanRepository** — SQLite storage with CRUD + find active loans, overdue loans, member loan history, book loan history
9. **LibraryService** — business logic:
   - borrow_book(member_id, book_id): checks availability, creates loan, decrements copies
   - return_book(loan_id): sets return_date, updates status, increments copies
   - get_overdue_loans(): returns loans past due_date
   - renew_membership(member_id): toggles is_active
   - search_books(query): searches across title/author/isbn
10. **CLI interface using click** with commands:
   - `library book add --title --isbn --author-id --published-year --copies`
   - `library book list [--author] [--available-only]`
   - `library book search --query`
   - `library member add --name --email`
   - `library member list [--active-only]`
   - `library borrow --member-id --book-id`
   - `library return --loan-id`
   - `library overdue`
   - `library member history --member-id`

Use type hints throughout. Use SQLite with foreign keys enabled. The database schema must enforce referential integrity with CASCADE deletes. Follow clean architecture with proper separation of concerns. All IDs must be auto-incremented primary keys that are optional (default None) in the domain models.

## Explicit behavior for the ESUS generation test

Treat these details as requirements, not implementation choices:

- Every `Book` has exactly one required `author_id: int` foreign key to `Author.id`. Deleting an author cascades to that author's books; deleting a book cascades to its loans.
- Add `library author add --name --birth-year [--biography]` so the CLI can create an author before a book. `--biography` is optional text.
- `library book add --author-id` requires an integer author ID. `--copies` is optional and defaults to one. `library book list --author` accepts an integer author ID and filters on `Book.author_id`.
- `--available-only` is a no-value boolean flag. When present, it returns books with at least one available copy; when absent, it does not filter by copy count.
- `library book search --query` performs case-insensitive substring matching across book title, author name, and ISBN. Return each book once even if multiple fields match. An ISBN miss returns an empty list.
- `Member.membership_date` defaults to today's date when a member is created, so `library member add --name --email` is sufficient. New members start active.
- A new loan is due 14 calendar days after its loan date. `LibraryService` computes the due date from a date value and passes it to the repository; the repository must not derive dates from `published_year`.
- Zero available copies is valid. Reject only negative copy counts. Borrowing the final copy leaves the count at zero.
- A loan is overdue when `due_date < today` and `return_date is None`. A late loan may still be returned. Returning sets `return_date` to today, sets status to `returned`, and restores exactly one available copy.
- Returning an already returned loan raises `AlreadyReturnedLoanError` and changes neither the loan nor inventory. Include that error in the declared error set.
- Without a background scheduler, report overdue status as a derived read result while the stored status remains `active` until the loan is returned.
- Borrowing and returning each perform all related writes in one SQLite transaction. If any write fails, roll back every write in that operation.
- When an ID field defaults to `None`, annotate it `int | None`. Preserve SQLite auto-increment for IDs and enforce the declared unique ISBN and email constraints.
